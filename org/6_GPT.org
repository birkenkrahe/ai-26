#+TITLE: In-Class Exercise (≈30 min): Build a Tiny Custom GPT (Task Agent)
#+AUTHOR: DSC 482 — Coding in an AI World
#+OPTIONS: toc:nil num:nil

* Purpose

- In this exercise you will design a small *task agent* using a Custom
  GPT.
- The goal is not to get a “good answer.” The goal is to practice
  turning a vague task into a *clear specification* that an AI system
  can follow.

- If you cannot specify the task clearly, an agent cannot perform it
  reliably.

* What you will produce

By the end of this exercise you should have:

- One small task specification
- One Custom GPT based on that specification
- Two short test runs
- One improvement you made after observing a failure

Work in *pairs*.

* Step 1 — Choose a task (2 minutes)

Choose a small task that you do regularly.

Requirements:
- It should involve *steps*
- It should have *clear inputs and outputs*
- It should be possible to test quickly

Examples:

- Generate a short study plan
- Extract action items from meeting notes
- Improve an email subject line
- Suggest a short workout plan
- Summarize a short text and generate review questions

Write your task in one sentence.

Example: Literature review
#+begin_quote
Given a research topic, produce search keywords and 3–5 research
questions that could guide a literature search.
#+end_quote

* Step 2 — Write the task specification (3 minutes)

Before building the GPT, define the task clearly.

Fill in the following fields.

Goal:
#+begin_quote
What is the task trying to achieve?
#+end_quote

Inputs:
#+begin_quote
What information must the user provide?
#+end_quote

Outputs:
#+begin_quote
What should the agent produce?
The result must be something you can check.
#+end_quote

Verification:
#+begin_quote
How can the user tell if the result is correct or useful?
Write 1–2 simple checks.
#+end_quote

** Example:

Task:
#+begin_quote
Transform a short research topic description into a structured
literature-search plan.
#+end_quote

Goal:
#+begin_quote
Help start OS research quickly and systematically.
#+end_quote

Inputs:
#+begin_quote
1. research topic
2. short description
3. optional focus
#+end_quote

Outputs:
#+begin_quote
The GPT should produce four structured elements.
1. Search keywords: 3-5 keyword groups covering core concepts,
   algorithms or techniques, architecture, modern research directions.
2. 3-5 combined search queries to be pasted into scholarly databases.
3. 3-5 research questions that should be conceptual, guide a
   literature search, and not require original experiments.
4. 3-5 ways to narrow the research topic if it becomes too broad.
#+end_quote

Verification:
#+begin_quote
1. Structural checks: The output must include:
   - keyword list
   - search queries
   - research questions
   - narrowing directions
2. Quality checks: Research questions should
   - be answerable through existing literature
   - not be purely factual
   - not require experiments
   - be relevant to operating systems design
3. Practical check: I should be able to
   - paste at least one search query into Google Scholar
   - find multiple relevant papers
   within the first results page.
#+end_quote

** Example

System prompt:
#+begin_example
You are a task agent that helps the user complete a repeatable task.

TASK GOAL: Generate a structured literature-search starting point for
a research topic in Advanced Operating Systems. The task helps
students turn a short topic description into a usable literature
search plan including keywords, search queries, research questions,
and possible focus directions.

INPUTS:
Ask the user for the following information:
- Research topic title
- Short description of the topic (1–5 sentences)
- Academic level (undergraduate, graduate, or mixed)
- Optional focus area (examples: kernel design, distributed systems, virtualization, security, performance, scheduling, memory management)

OUTPUT:
Produce the following result:
A structured literature-search plan that includes:
- Search keyword groups (core concepts, algorithms/mechanisms,
  architecture, modern research directions)
- 3–4 example academic search queries that can be used in Google
  Scholar, ACM Digital Library, IEEE Xplore, or arXiv
- 3–5 research questions suitable for a literature review
- 3–5 possible directions to narrow the topic if it is too broad

RULES:
1. Ask clarifying questions if information is missing.
2. Do not invent facts or specific papers.
3. Present results in short structured sections.
4. Keep answers concise.
5. Research questions must guide literature exploration and not
   require original experiments.
6. Focus on operating systems design, algorithms, and systems architecture.

OUTPUT FORMAT:

Inputs received:
- Topic:
- Description:
- Level:
- Focus (if provided):

Plan or result:

Search keywords:
[Grouped keyword lists]

Example search queries:
[List of realistic queries]

Research questions:
[3–5 questions]

Possible focus directions:
[3–5 narrowing options]

Verification checklist:
- Do the research questions explore design, algorithms, or system trade-offs?
- Can at least one search query return multiple academic papers?
- Are the keywords specific enough for scholarly databases?
- Are the questions answerable through existing literature?
#+end_example

* Takeaway

Agents fail where humans rely on:
- vague language
- unstated assumptions
- missing inputs
- lack of verification

Designing a reliable agent means turning a task into:

1. Goal
2. Inputs
3. Outputs
4. Verification
